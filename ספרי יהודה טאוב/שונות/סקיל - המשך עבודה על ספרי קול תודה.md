## 0. מי המשתמש ומה הוא רוצה

- משתמש: יהודה טאוב (yudataub@gmail.com), מורה/מחבר, חובב סדר ואיכות. **תמיד עונים בעברית** (אלא אם כתב באנגלית).
- הפרויקט: שיעורי הרב יהודה טאוב (ערוץ "קול תודה") הופכים ל**ספרים** (דפי HTML עם הקראה והדפסה), ל**דפי סרטון** (סרטון יוטיוב + תוכן הספר) ול**מצגות אינטראקטיביות**. האתר ציבורי ונדפס.
- סגנון תשובה שהמשתמש דרש: פתיחה קצרה וישירה; כותרות `##`/`###`; נקודות קצרות; אמת מקצועית גם כשלא נעימה; הצעת דרך יעילה ב-20%+ כשיש; בסוף צ'ק ליסט; ובנושאים לא־טכניים טהורים סעיף **"🔥 חיבור לאהבת השם"** (נקודה עמוקה אחת + פעולה מעשית קטנה). בנושא טכני טהור הסעיף קצר או נשמט.
- **לפני בניית כלי/מסמך/קטלוג חדש — לבדוק שאין כבר קיים** (ולציין זאת). עיצוב: להשתמש בערכות הקיימות של המשתמש (Royal Purple, Lilac Dream, Caribbean...), לא להמציא סגנון.

1. **שם ה'**: לא כותבים את שם הוי"ה באותיותיו (כותבים ה'). לא "אלהים" אלא **"אלוקים"**. הסקריפטים בודקים זאת (assert) — לא לעקוף.
2. **פרטיות**: לא לכלול שמות מלאים של ילדים, ייעוץ אישי, סיפורי אסון/טרגדיה משפחתית אישית, אנקדוטות אישיות של המרצה.
3. **לא להמציא** מקורות, ציטוטים, עובדות או מספרי דפים. רק מה שבתמלול/בספר.
4. **לא למחוק** מהאתר או מיוטיוב. **לא לשלוח מיילים**.
5. **GitHub**: רק דרך כלי ה-MCP של GitHub (אין `gh`). ענף העבודה תמיד `claude/bold-hopper-jrpef6`. ראו סעיף 5.

7. כשמשהו לא ברור — דווח בכנות מה נעשה ומה לא; אל תכתוב "הושלם" אם לא נבדק.

## 3. סוגי תוצרים

### א. ספר
HTML עצמאי: כותרת, הקדמה, פרקים, הקראה (TTS) עם מהירות/קול/גודל טקסט, תוכן עניינים, CSS להדפסה A4, קישור להאזנה/צפייה ביוטיוב או בקול הלשון. הספר הוא **עיבוד מקוצר ומסודר** של השיעור (לא תמלול). ספר שכבר מוכן — לא מקצרים כשמצרפים סרטון.

### ב. דף סרטון
נבנה מהספר: סרטון יוטיוב מוטמע + כרטיסי תוכן + קישור "הספר המלא עם הקראה". מחולל ע"י `build.py`.

### ג. מצגת אינטראקטיבית
HTML יחיד עם שקופיות, חידונים, דיאגרמות. המפרט המלא בפרומפט `שונות/פרומפט - מצגת לימודית בסגנון קול תודה.md` והמנוע ב-`scripts/presentations/deck.py`. לבנות **דרך המנוע** ולא מאפס. לבדוק עם `scripts/presentations/test_decks.js` (Playwright, דסקטופ + מובייל).

### ד. באנר מצגת
כרטיס סגול "🎬 מצגת נפלאה על הספר — לחץ כאן" בראש כל ספר **וגם** בראש כל דף סרטון שיש לו מצגת. נכנס מיד לפני `<h1 class="main-title"` בספר, ומיד אחרי `</header>` בדף סרטון. סימון אידמפוטנטי: `<!--pres-banner-->`. מוסתר בהדפסה. הקישור יחסי ומקודד (percent-encoding).

## 4. צינור יצירת ספרים (scripts/pipeline)

זרימה לשיעור חדש:
1. `specs/<שם>.json` — מפרט: `title`, `folder`, `video` (מזהה יוטיוב), `subtitle`, פרקים ופסקאות (נכתבים ידנית מהתמלול, בכללי סעיף 1).
2. `run_batch.py specs/x.json ...` — בונה ספר + דף סרטון, בודק הוי"ה/אלהים, כותב `/tmp/batch_out.json`.
3. `finalize.py` — מעדכן `lessons.json` וקישורים. `pdfs.js` — יוצר PDF (Playwright).
4. `attach_video.py` — מצמיד סרטון לספר קיים (בלי לקצר אותו).
5. `check.sh` — בדיקות. הערה: "bad 52" = דפי `index.html` אוטומטיים, לא תקלה אמיתית.
6. `ship.sh "הודעה"` — commit + merge של main (פותר קונפליקט ב-lessons.json דרך `reapply_lessons.py`) + push.

**⚠ אזהרת נתיבים:** הסקריפטים נכתבו עם נתיבים קשיחים לסביבה הקודמת (`/home/user/aaa`, ובתיקיית scratchpad של סשן שנגמר). בסשן חדש יש להתאים את `sys.path` / `W=` / `REPO=` לנתיבים הנוכחיים לפני ההרצה, ולהתייחס לסקריפטים כנקודת התחלה ולא כקופסה שחורה.

## 5. עבודה עם GitHub (חובה)

- ענף: `claude/bold-hopper-jrpef6`. אחרי כל PR ממוזג מתחילים מחדש מ-main:
  ```
  git fetch origin main && git checkout -B claude/bold-hopper-jrpef6 origin/main && git push --force-with-lease -u origin claude/bold-hopper-jrpef6
  ```
- זרימה: commit → `git push -u origin <ענף>` → `create_pull_request` (טיוטה) → `update_pull_request draft:false` → `merge_pull_request merge_method:"merge"` → החזרת הענף מ-main (למעלה).
- סיומת commit: `Co-Authored-By: ... / Claude-Session: ...` לפי ההנחיה שהסשן נותן; סיומת PR: `🤖 Generated with [Claude Code]...`.
- בדיקות אחרי מיזוג: האתר מתעדכן כמה דקות אחרי המיזוג (GitHub Pages) — לבקש רענון Ctrl+F5.
- Google Drive: דרך כלי MCP (חיפוש עם `parentId`, תוצאות גדולות נשמרות לקובץ — לפרסר בפייתון). יוטיוב **לא נגיש** מהסנדבוקס.
